# 9.3 Grace across runs

Written 2026-10-17. Run 2026-10-17, 17:00Z to 19:10Z; passed, with two findings.

**Question this can falsify:** that a destructive act's warning posted by run A is honoured by run B
inside the grace (the act refused, `graceRunning`) and acted on by run C after it; that a `/working`
comment between A and C cancels; and that a deleted warning re-warns rather than acts.

## Setup

- The common sandbox: a personal repository whose workflow checks out `hiero-hackers/sdk-automations` at the
  commit under test, builds the bundle (`pnpm install --frozen-lockfile && pnpm --filter
  @hiero-hackers/automation-runtime build:action`) and runs `uses: ./`. The run summary and the Actions
  log are the evidence. Where the real event is hard to provoke, a `workflow_dispatch` writes the
  captured payload to `GITHUB_EVENT_PATH` and runs the same step. Record the commit at step 1.
- Config `mode: active` with the capability whose destructive act is under test (the inactivity
  unassign or close) enabled and its grace set as short as the config allows; `arm-writes: "true"`.
- Two fixtures that have been idle past the threshold, and a third for the deletion case. Triggering
  runs are `workflow_dispatch` or the hourly schedule; the time of each is recorded.

## Steps

1. Run A on fixture 1. Expect a warning comment and no act. Read the comment's marker: it must carry
   the act's record. Note its created time.
2. Run B inside the grace. Expect the act refused with `graceRunning`, no new comment, no write.
3. Wait out the grace. Run C. Expect the act applied once, the summary naming the warning it read back.
4. Fixture 2: run A, then a person comments `/working`. Run C after the grace. Expect no act and a
   summary showing the cancellation.
5. Fixture 3: run A, then the maintainer deletes the warning comment. Run C. Expect a new warning
   (re-warn), not the act, and a fresh grace starting at the new comment.
6. Lay the comment timelines beside the run times; each outcome must follow from them alone.

## Expected result

Three outcomes in three run summaries (refused in grace, acted after it, cancelled by `/working`),
the comment timeline matching them, and the warning's marker carrying the record. A deleted or
undated warning re-warns.

## What migrated

Row D231 in `design/history/decisions.md`: a sweep's first write answered with a fresh core window,
and the allowance took it for a roll; the `spent.core` of 10 and 5 in runs C and D, against 389 and
386 in A and B for the same 180 items, is how it showed. The `/working` re-warn by rewrite with no
cancellation row in the summary is an issue draft.
