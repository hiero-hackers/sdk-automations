# 8.3 Close on a mode claim

The first armed run of the destructive ladder's close path, against the personal
sandbox, on 2026-09-12. Two runs: the morning's, which decided the close and could
not send it; the afternoon's, after protocol 6.10 confirmed the endpoint, which sent it.

## Question

That a close decided on a pull request's MODE (D157) is warned first, lands once after
the grace, refuses when the mode moved before the deadline, and is never re-done after
a human reopens.

## Red line

One repository, the lead's sandbox; two draft pull requests the lead opened for the
purpose; every write App-authored and reversed by the lead as a human before the
protocol closed. `remindAfter: 0h` and `reap.after: 2h`, the floor — a configuration no
real repository would carry.

## Method

| Fixture | State | Made by |
|---|---|---|
| #179 | a draft, marked ready for review after its warning | the lead |
| #186 | a draft, untouched | the lead |
| `sdk-automations.yml` | `mode: active`, inactivity with `pullRequests.reapWhen.draft.reap.enabled: true` | the lead, on `main` |

The shell armed from `tidy/config-layer`, `SWEEP_CADENCE_HOURS=1`, a fresh store; restarted from
`lab/protocol-6.10` for the second run on the same store.

## What this run found

- Warning → grace → close on a mode claim → notice → human reopen left alone: proven live.
- A mode that moved before the deadline is left alone at decision time: #179. The apply-time
  refusal (`preconditionStale`) stays proven by the injected suite; live timing cannot hit it.
- Three defects in the store's memory of an act, fixed by C23 (D160) and the ledger rebuild (D161):
  a refusal the platform could not send was settled as done; a state read from the last journal
  row alone treated a gap as completion; an abandoned act would have been followed by its notice.
- The sweep persisted no per-item decision, so explaining a silent pass took an hour (D163).
