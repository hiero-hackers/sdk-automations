# 9.4 Same-second events

Written 2026-10-17. Run 2026-10-17 on `exploreriii/automation-sandbox`: PASSED.

**Question this can falsify:** 8.6's same-second label changes, now as two runs under the example
workflow's concurrency group keyed by issue number: that one unlock transition lands on GitHub, the
second run's call is idempotent, and no run that mattered is lost to the group.

## Setup

- The common sandbox: a personal repository whose workflow checks out `hiero-hackers/sdk-automations` at the
  commit under test, builds the bundle (`pnpm install --frozen-lockfile && pnpm --filter
  @hiero-hackers/automation-runtime build:action`) and runs `uses: ./`. The run summary and the Actions
  log are the evidence. Where the real event is hard to provoke, a `workflow_dispatch` writes the
  captured payload to `GITHUB_EVENT_PATH` and runs the same step. Record the commit at step 1.
- The example workflow's `concurrency` block as written (`group` keyed by issue number,
  `cancel-in-progress: false`). Config `mode: active`, `triageQueue` with `lockUntilTriaged` and
  `confirmUnlock`, `arm-writes: "true"`. A locked fixture issue carrying the triage label.
- GitHub keeps one pending run per group and cancels an older pending run when a newer one queues.

## Steps

1. Record the commit. As one person, in one gesture, remove `status: triage` and add
   `status: ready for dev` (the label picker). Record both timeline times.
2. Read the two runs. Expect the second to start only after the first ends; record whether any run
   shows "cancelled" by the group.
3. Expect one unlock transition on the issue timeline and one confirmation comment. The second run's
   unlock reads `already` or `preconditionStale`; record which.
4. If a queued run was cancelled, read the item's final state: label set, lock and comments must
   be what the surviving run alone would produce. Re-run the cancelled run by hand and expect no write.
5. Repeat three times, varying the gap between the two changes (same second, one second, five).
6. Restore the fixture: unlock, close, config as before.

## Expected result

One unlock transition on GitHub; the second run's call idempotent; no run lost that mattered, and
where the group cancelled a queued run, the item's final state is still right.
