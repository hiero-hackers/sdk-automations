# 7.1 — Capture webhook payloads as normalizer fixtures

**Customer:** `packages/core/src/engine/events.ts` (born `core/github/events.ts`; moved in D92 phase 5). The normalizer must be built against real GitHub payloads.
Era-1's payload copies exist only in the private unscrubbed archive (complete bodies, commit-author
emails — see the lab README), so they can never become tracked fixtures; fresh
captures through the scrubbing receiver are the only trustworthy source (D87, corrected 2026-08-06).

**Instrument:** `src/capture.ts` — an HMAC-verified receiver that scrubs every payload through
`src/scrub.ts` **before anything touches disk**, writing to the untracked `evidence/pending/`.

## Scrubbing rules (written before the first capture — D87's condition)

Deterministic replacement, never deletion, so fixtures keep referential structure:

1. Account/org/repo identifiers (`login`, `slug`, and `name`/`full_name` on account-shaped
   objects) → `scrubbed-N`, stable within a payload, and rewritten inside every string value
   (URLs included).
2. Database ids (`id`, `database_id`, `installation_id`, `hook_id`) → small sequential integers,
   stable within a payload.
3. Every `node_id` → `SCRUBBED_NODE_ID`; every email → `scrubbed@example.invalid`.
4. Workflow **content is untouched**: actions, numbers, titles, bodies authored for the
   experiment, and label names — label strings are the mapping layer's subject matter.
5. `description` fields are blanked wholesale, and full-length git shas are replaced
   deterministically (40-digit stamps, references preserved). Both added 2026-08-07 by the
   first real capture run: neither is identifier-shaped, so the identifier passes missed
   them, and only the protocol's read-every-file step caught the residue.

## First run — 2026-08-07

Ten captures from seven sandbox actions via an smee relay. Five promoted to
`packages/dev/testkit/fixtures/` (they landed in core and moved with the testkit's creation): issues
opened/labeled/closed, pull_request opened/closed(merged).
Held in pending: `label.created` and four `push` events (no observation kind consumes them yet).
Not capturable: `review_requested` — GitHub refuses self-requests, so it waits for a second
sandbox account. The exhaustive string scan ran clean after rule 5 landed.

The rules are enforced by `test/scrub.test.ts`, including the leak list and the
structure-survival properties.

## Second run — 2026-10-02

Protocol 7.2's first probe left six scrubbed deliveries in pending; `issue_comment.created` promoted
(the commenter is the App itself; `performed_via_github_app.client_id` blanked by hand, a rule the
scrubber does not yet carry). The other five already have fixtures.

## Procedure

1. Point the sandbox App's webhook at the receiver (`pnpm --filter automation-lab capture`, via a
   tunnel). Sandbox repository only — P8's ground rule is unchanged.
2. Provoke one delivery per observation kind in core's catalogue: issue opened / labeled / closed,
   pull request opened / review requested / merged, and the schedule-adjacent events as they gain
   protocols. The **catalogue is the shopping list** — a capture with no observation kind waiting
   for it is not collected.
3. Read each scrubbed file in `evidence/pending/` end to end. Only then move it INTO the testkit, as
   `packages/dev/testkit/fixtures/<event>.<action>.json`, and add it to that package's capture list —
   fixtures must reach their consumers through a package EXPORT rather than a path, which is what
   carries them into a mutation sandbox. This protocol shares its trigger with the normalizer work,
   so there is no interval in which a waypoint would hold them. Nothing under `lab/` tracks
   evidence at all.

## Exit

Done when every observation kind in the catalogue has at least one fixture in the testkit, and
`events.ts` tests import them. Evidence of completion: the testkit's exported capture list.
