# 9.7 Budget

Written 2026-10-17. Not yet run.

**Question this can falsify:** that the hourly sweep on a repository with 300 open items stays
under the 1,000 requests per hour the runner token has, and that the allowance defers the rest to
the next run.

## Setup

- The common sandbox: a personal repository whose workflow checks out `hiero-hackers/sdk-automations` at the
  commit under test, builds the bundle (`pnpm install --frozen-lockfile && pnpm --filter
  @hiero-hackers/automation-runtime build:action`) and runs `uses: ./`. The run summary and the Actions
  log are the evidence. Where the real event is hard to provoke, a `workflow_dispatch` writes the
  captured payload to `GITHUB_EVENT_PATH` and runs the same step. Record the commit at step 1.
- 300 open items on the sandbox: create them with a script that paces its writes, in batches, never
  faster than the sandbox tolerates (bounded hostility; stop at any secondary-limit answer).
- Config `mode: dry-run`, `triageQueue` and `prDashboard` enabled, `arm-writes: "false"`. Nothing else
  uses the token in the hour: check `GET /rate_limit` before and after.

## Steps

1. Record the commit and `GET /rate_limit` (core and graphql) before the sweep.
2. Trigger the sweep by `workflow_dispatch` or the hourly schedule.
3. In the log find `sweepFinished`: record `items`, `decided`, `remaining`, `resumeAfter`, `reused`
   and `spent` per lane. Spend must be under the pool.
4. Record `GET /rate_limit` after; the drop must agree with `spent`.
5. Search the log for secondary-limit answers (403 or 429 with a retry-after). Expect none.
6. Trigger the next sweep. Expect it to start at `resumeAfter`, decide the `remaining` items, and
   reuse stored reads for items unchanged (`reused`).
7. Continue until `remaining` is 0; record how many runs 300 items took.

## Expected result

`sweepFinished` spend under the pool in the log; no secondary-limit answer; the next run continues
where the first stopped. 9.1's sweeps on 175 to 180 items spent 376 to 389 core calls, about two a
cold item, so one hourly run under a 1,000-request token reaches about 450 items before the
allowance defers the rest.
